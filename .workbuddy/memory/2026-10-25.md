# 2026-10-25

## SnipForge 从零搭建（Windows 截图/剪贴板/图床一体化工具）

### 技术选型转折

- 初版用 Electron 写了一大半（主进程模块、插件系统、图床 providers 全部完成，约 20 个文件）。
- 老板指出本机有 Rust —— 实际核查发现是 **FlyEnv 装的半套 rustc**：只有编译器本体，没有 cargo、没有 MSVC 链接器、没有 Windows SDK。
- 给了三条路，老板选 **补齐 Rust 后切 Tauri**。Electron 代码归档到 `_archive/`，前端 React 部分基本复用。

### 环境搭建踩坑（重要，下次直接照做）

1. `winget install Rustlang.Rustup` 报"已安装"但 `~/.cargo` 不存在 —— 是残留注册记录，改用下载 rustup-init.exe 手动装。
2. 首次 rustup 装完 **rust-std 的 lib 目录是空的、cargo.exe 缺失**（"recovering from a partially installed toolchain"），必须 `rustup toolchain uninstall` 再重装。
3. **MSVC 链接器必须单独装**：`winget install Microsoft.VisualStudio.2022.BuildTools --override "--quiet --wait --norestart --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"`。第一次带 `--disable-interactivity --nocapture` 报 exit 87，去掉就好了。安装会自动带 Windows SDK（10.0.26100），耗时约 10 分钟。
4. **Git Bash 的 PATH 里有 coreutils 的 `link.exe`**，会让 rustc 报 `link: extra operand`。解决：`~/.cargo/config.toml` 里显式指定 MSVC linker 绝对路径。
5. crates 镜像用 rsproxy.cn（写入 `~/.cargo/config.toml` 的 source replacement），拉依赖快很多。

### 关键技术决策

- **逐屏一个覆盖窗口**，不做跨屏大窗口。原因：WebView2 一个窗口只认一个 DPI 基准，横跨不同缩放的两块屏必然错位。用 `PhysicalPosition` 定位绕开 DIP 换算。
- **剪贴板用 `GetClipboardSequenceNumber` 轮询**做变更检测，零开销，比"每 500ms 读内容比对"省一个数量级。Electron 版只能读 availableFormats，这个 Rust 版明显更优。
- **OCR 用 Windows.Media.Ocr**，不引 tesseract。WinRT 异步用"轮询 Status + GetResults"同步等待（windows-future 的 `Async` trait 是私有的，不能直接 `join()`）。
- **S3 手写 SigV4**（约 100 行 + hmac crate），不引 aws-sdk（几十 MB）。
- **插件主推声明式**：`*.uploader.json` 放进插件目录就能接任意 HTTP 图床，`{{key}}` 插值配置值，`config_fields` 自动生成表单。理由是安全：能配 JSON 就接上的图床，比要签名的 DLL 安全一个量级。
- 长截图拼接用**行签名暴力匹配**（24 个采样点/行，亮度加权），不用特征点。因为我们控制着"一屏滚一次"，搜索范围极小。

### 编译期踩坑（Tauri 2.12 具体 API）

- `windows::Win32::Foundation::BOOL` → 新版在 `windows::core::BOOL`
- `EnumWindows` 第一参数要 `Some(enum_proc)`
- `GetWindowThreadProcessId` 第二参数 `Option<*mut u32>`
- `WebviewWindow` 没有 `emit_to` / `once` / `set_opacity`，需要 `use tauri::Emitter`
- `capabilities/default.json` 里 **`core:window:allow-set-opacity` 已被移除**，写了会 build 报 "permission not found"
- `GetSoftwareBitmapAsync()` 无参；`GetSoftwareBitmapTransformedAsync` 需要 5 个参数（含 ExifOrientationMode + ColorManagementMode）

## 第二轮：三个用户反馈问题的修复

### 1. 截图确认按钮点不动
**原因**：`onMouseDown` 绑在 `.selector-root` 上，工具栏按钮是其子节点，
点按钮的 mousedown 先冒泡到 root，被当成"开始新选区"，于是永远点不到按钮。
**修法**：把交互层抽成 `.selector-surface`（只包背景+遮罩），工具栏作为**兄弟节点**，
结构上隔离；工具栏再加 stopPropagation 兜底。比加一堆判断干净。

### 2. 剪贴板没有记录
**原因**：`is_suppressed()` 的跳过逻辑写错了顺序 ——
先更新 `last_sequence` 再 `continue`，导致抑制期内的变化被**永久丢弃**。
截图后点"复制"正好走 `copy_image_bytes` → `suppress(900)` → 自己写的图片永远进不了历史。
**修法**：删掉跳过逻辑。自己写的内容也入库，重复内容靠 hash 去重（命中只 touch 提到最前）。
这本来就更符合剪贴板管理器的预期。

### 3. OCR 增强
改成可插拔引擎：
- `ocr/mod.rs` 引擎管理器 + `EngineInfo`
- `ocr/windows.rs` 原有 WinRT 实现
- `ocr/paddle.rs` 外部 [PaddleOCR-json](https://github.com/hiroi-sora/PaddleOCR-json) 调用
- 配置项 `ocr.engine` / `ocr.paddlePath` / `ocr.timeoutSecs`
- 外部引擎找不到或失败**自动回退** Windows，不整个失效
- 引擎本体不进安装包（坚持 2.4MB），用户放 `%APPDATA%/fun.lxzt.snipforge/ocr-engines/`

PaddleOCR-json 调用细节：`-image_path=xxx.png` 一次性命令行，stdout 出 JSON
`{"code":100,"data":[{"box":[[x,y]...],"text":"...","score":..}]}`，code 101=无文字。
用宽松 JSON 取值而非强类型结构体（版本间字段有出入）。`CREATE_NO_WINDOW` 防黑窗。

### 验证方法沉淀
`snipforge.exe --smoke` 现在覆盖：屏幕捕获 / 预览编码 / 窗口枚举 / OCR 双引擎 /
剪贴板序列号变化 / 文本写读 / 图片写读 64×32。全绿。
端到端另测：启动应用 + `Set-Clipboard` 写标记 → 日志出现"剪贴板收录: text" → history.json 命中。

## 第三轮：美化/水印实时预览 + OCR 一键下载

### 美化、水印"无效"的真正原因
不是逻辑错，是**架构错位**：美化和水印只在 `composeFinal()`（导出时）生效，
编辑器画布上从头到尾只画原图+标注。用户拖滑块看不到任何变化，自然会认为功能坏了。

**修法**：把预览拆成三层，都用同一套尺寸公式保证所见即所得：
1. `.stage-artboard` —— CSS 承担内边距/圆角/背景/阴影（实时、零成本）
2. `.stage-canvas-holder` —— 画布本体 + 圆角裁剪
3. `.wm-layer` —— 水印绝对定位层

关键：`layout` useMemo 里按 `composeFinal` 完全相同的公式算输出尺寸
（原图+padding → aspect 扩边 → 等比缩放到可用空间），再用该 scale 把原始像素参数
换算成 CSS px。否则预览和导出会不一致。

### 补齐的功能
- 阴影强度 0-100 无级调节（之前固定值）
- 背景：6 套渐变预设 + 任意纯色（color picker）+ 透明
- 输出比例：原始/1:1/4:3/3:2/16:9/9:16，**只扩边不裁图**（截图工具不能偷裁内容）
- 水印：字号可调、单行/平铺(-30°)、不透明度
- 水印开关打开时自动填默认文案 "SnipForge" —— 否则开了开关什么都没发生，又是一个"无效"

### PaddleOCR 一键下载
官方包是 **88MB 的 7z**，Windows 资源管理器根本不支持 7z ——
用户要自己下解压软件，这一步劝退率极高。所以托管全流程：
GitHub API 查最新 release → 流式下载（200ms 节流上报进度）→ **sevenz-rust 纯 Rust 解 7z**
→ 递归找 exe → 自动设为当前引擎。

- 依赖加 `sevenz-rust = "0.6"`（体积 +40KB），不调外部解压工具
- 进度事件 `ocr://download`，前端画进度条
- 下载源是 GitHub，不通会明确报"可能需要代理"，不假装成功

### 验证
`--smoke` 8 项仍全绿。下载链路用 curl 验证过 GitHub API 返回 3 个 asset
（v1.4.1 只有 `PaddleOCR-json_v1.4.1_windows_x64.7z` 88MB）。

### 美化：窗口外壳（参考 QuickShot）

加 `color` 字段，7 色预设 + 任意取色。canvas 绘制时加 `shadowBlur`，
浅色文字压亮背景也能看清，不用给用户额外描边参数。

### 剪贴板来源
`GetClipboardOwner()` → PID → 进程名，这是**精确**答案（谁持有剪贴板谁复制的）。
很多应用复制完立刻释放所有权，所以回退到前台窗口；自己写剪贴板时排除自身。
实测写入剪贴板能正确识别为 `powershell`。

### 接管 Win+V
**Windows 把 Win+V 当系统保留热键，第三方 RegisterHotKey 一律失败** —— 这点必须说清楚，
不能假装能抢。真正的"接管"= 写注册表关掉系统剪贴板历史：
`HKCU\Software\Microsoft\Clipboard` / `EnableClipboardHistory` = 0（走 reg.exe，不引外部库）。
然后用户用本工具的面板快捷键（默认 Alt+V）。

### 敏感过滤默认关
`skip_sensitive` 默认改 false，保留能力但默认不启用（误伤正常文本比少存一条代价大）。
**踩坑**：加了 `config::migrate()` 但忘了落盘，导致老配置仍是 v1、过滤仍开着。
修法：迁移后如果版本变了立即 `persist_settings()`。

### 托盘图标
`icons/tray.png` 之前生成的是 **mono 白色版**（191 字节），在浅色任务栏上等于隐形。
改成彩色 `drawIcon(32)`（1778 字节）。

### 托盘菜单
`MenuItem::with_id` 的 accelerator 参数传各功能快捷键，菜单右侧显示 `Alt+Q` 等。
注意 `accel` 闭包不能返回 `Option<&str>`（生命周期问题），要返回 `Option<String>` +
调用处 `.as_deref()`。

- settings.json 迁移到 `version=2 skipSensitive=False` ✓
- 安装包 2.45 MiB，内存 26.9MB

## 第五轮：Win+V 接管（考证 TieZ 做法 + 实测推翻 + 钩子实现）

### TieZ 到底怎么做的
读源码（`src-tauri/src/app/commands/hotkey_cmd.rs` + `system_cmd.rs`）：

1. `trigger_registry_win_v_optimization(true)`：
   - `HKCU\...\Explorer\Advanced\DisabledHotkeys` 追加 `V`
   - `HKCU\Software\Microsoft\Clipboard\EnableClipboardHistory` = 0
   - `EnableCloudClipboard` = 0
   - 清理组策略覆盖（`DisallowClipboardHistory` / `AllowClipboardHistory` / `AllowCrossDeviceClipboard`）
   - 变更后 `restart_explorer()`：`taskkill /F /IM explorer.exe & start explorer.exe`
2. 然后 `global_shortcut().register(Super+V)`，代码注释写着
   "Windows disables Explorer's Win+V handler before assigning it to TieZ"
3. 注册失败就走错误分支："快捷键设置失败，请换一组按键"

### 实测结论（本机验证）
- 当前状态：`DisabledHotkeys='V'`、`EnableClipboardHistory=0`，但 `RegisterHotKey(Win+V)` **仍失败**
- 对照组 `RegisterHotKey(Win+F12)` **成功** → 说明不是 API 用法问题，就是 Win+V 被占
- 重启 explorer 后再试 → **仍然失败**

结论：**改注册表并不释放 Win+V**。Win+V 由 ShellExperienceHost 在登录时占住，
和 explorer 的 DisabledHotkeys 无关。TieZ 那句注释是作者的假设，未必成立；
它的 Win+V 支持在多数环境下会走到"请换一组按键"。

### 真正可行的方案
`WH_KEYBOARD_LL` 低级键盘钩子 —— 在按键进入系统之前截住。

TieZ 其实已经装了钩子（`app/setup.rs::init_win32_hooks`，用于快速粘贴数字键、导航键），
但**没有**用来拦 Win+V（`grep 0x5B` 只在修饰键判断里出现）。

我的实现：`src-tauri/src/win32/keyhook.rs`
- 独立线程 + 消息循环（钩子必须在有消息循环的线程安装）
- 回调只做：判断 vkCode==V && 只有 Win 修饰 && 非注入 → `LRESULT(1)` 吞掉 + `async_runtime::spawn` 弹面板
- **回调里绝不做重活**：超过 1 秒系统会静默摘钩
- `LLKHF_INJECTED(0x10)` 检查，避免自己模拟的按键触发
- 开关是 `clipboard.takeoverWinV`，关掉后钩子仍挂着但只放行

日志验证：`Win+V 键盘钩子已安装` + `Win+V 接管: 开启`。

## 第五轮：剪贴板改成 Tiez 式"就地粘贴"

### 用户的原话
"剪贴板的用法不对，按照 tiezi 的逻辑，我们应该在任何位置调出来点击对应内容就可粘贴到对应位置。"

### 之前错在哪
Win+V / Alt+V 弹的是**主窗口**（整个应用界面），点一条只是写剪贴板，
用户还得自己切回原窗口按 Ctrl+V —— 那和"看历史记录"没区别。

### 现在的链路（顺序错一步就不 work）
1. 快捷键触发时，**先**用 GetForegroundWindow 记下前台窗口（弹窗前必须记）
2. 弹出 `panel` 独立小窗：408×470，贴在光标旁，always_on_top + skip_taskbar + 透明
3. 用户点条目/回车 → 写剪贴板 → 收起面板
4. 焦点还给第 1 步记的窗口（SetForegroundWindow，失败则 AttachThreadInput 借前台资格）
5. 模拟 Ctrl+V

关键细节：
- **注入的按键不再过滤**。以前 keyhook 里判断 flags & LLKHF_INJECTED 就跳过，
  导致远程桌面 / AutoHotkey / 宏键盘发的 Win+V 全失灵。我们只会注入 Ctrl+V，
  不会注入 Win+V，所以没有自激风险。
- 面板窗口复用（首次创建后一直 hide），第二次呼出是瞬时的。
- Focused(false) 自动收起，点别处就消失，和系统 Win+V 手感一致。
- 目标窗口是自己进程时（从 SnipForge 界面呼出）退化成"仅复制"。

### 顺手修的：CF_HDROP
文件条目以前写入的是多行路径**文本**，粘到资源管理器是一串字符串。
新增 win32/clipboard.rs::set_files，手写 DROPFILES(20 字节头 + UTF-16 双\0 表)
+ SetClipboardData(CF_HDROP=15)。arboard 不支持文件列表，只能走原生。

### 验证方法（.tools/panel_e2e.py，7/7 通过）
自己用 Win32 造目标窗口不靠谱（ctypes 回调用错 argtypes 直接静默崩），
改成：记事本当目标 + 测试进程自己装 WH_KEYBOARD_LL 抓注入事件。检查项：
Win+V 弹面板 / 面板拿焦点 / 回车后焦点回到记事本 / 注入序列含 Ctrl+V /
剪贴板内容正确 / 记事本里只粘贴一次 / 面板收起。

注入序列实测：0xa2↓ 0x56↓ 0x56↓ 0x56↑ 0x56↑ 0xa2↑
—— keybd_event(scanCode=0) 会产生一次重复的 V down，但目标应用只当一次粘贴
（记事本文本里 marker 只出现 1 次），所以不需要换 SendInput。

### 其它
- 托盘菜单拆成「剪贴板面板(Alt+V)」和「剪贴板管理（主窗口）」
- capabilities 的 windows 列表加了 panel
- .tools/shot.py 是纯 ctypes 截图（GDI BitBlt + 手写 PNG 编码），
  因为本机终端工具的 Add-Type 路径被安全策略拦、python 又没装 Pillow

## 第六轮：编辑器滚轮缩放 + 钉图（F3 / Alt+P）

### 缩放
`zoom` state 乘进 `layout` 的 scale，一处改动让画布/内边距/外壳/水印字号全部等比缩放——
只要有一处漏了，"预览=导出"就废了。

两个坑必须记住：
1. **React 的 onWheel 是 passive 的**，preventDefault 拦不住，页面会跟着滚。
   要用 `addEventListener('wheel', h, { passive: false })`。
2. **光标锚点**：缩放前记下光标在画板里的相对位置（0-1）+ 屏幕坐标，
   缩放后在 effect 里用新 rect 反算，调整 stage.scrollLeft/Top 把它钉回去。
   少了这步，滚轮会变成"从左上角放大"，想看的内容越滚越远。
3. 居中不能用 `justify-content/align-items`（内容溢出时左上角滚不到），
   用 `.stage-artboard { margin: auto }` —— 小于容器自动居中，大于容器归零。

### 钉图
`windows::open_pin(app, data_url, img_w, img_h, opacity)`：
光标居中、屏幕 70% 收口、**不放大**；尺寸用 PhysicalSize（多屏不同缩放时 logical 会错）。
pin.html 现在：滚轮改窗口尺寸、双击/Esc 关、右键菜单（复制/另存/透明度/关闭）、悬停描边。
`Alt+P` = 钉剪贴板里的图（配置里一直有个 `pinFromClipboard` 但从没接线，补上了）。

### 踩到的大坑：同步命令 + 建窗口 = 主线程死锁
`image_pin` 一开始是同步 `#[tauri::command]`，点下去整个应用冻住（UI 线程 SendMessageTimeout 超时）。
原因：Tauri 的**同步命令跑在主线程**，而 `app.cursor_position()` / `monitor_from_point()`
内部是 `run_on_main_thread + 等结果` → 自己等自己。
改法：命令标 `async`（跑在 tokio 线程），解码丢 `spawn_blocking`。
`clipboard_pin` / `clipboard_pin_current` 同样改成 async，调用点（shortcuts.rs、tray.rs）
改成 `tauri::async_runtime::spawn` + `.await`。

对照：`panel::show` 里也调 `cursor_position()`，但它是由快捷键回调/异步任务调用的，不在主线程，所以没事。

## 第七轮：悬停滚轮调参 + 锥尾箭头

### 滚轮双用（用户要的"另一套缩放"）
不是新增一套缩放，而是**按鼠标位置分流**：
- 压在已画图形上 → 改它的参数
- 空白处 → 缩放画布（上一轮的逻辑原样保留）

参数映射集中在 `model.ts::shapeParam()`，加新工具只改一处：
| 类型 | 参数 | 范围 |
|---|---|---|
| rect/ellipse/arrow/pen | strokeWidth | 1-24 |
| text | fontSize | 10-96 |
| number | radius | 8-64 |
| marker | alpha | 6%-90% |
| mosaic | blockSize | 3-48 |

三个关键设计：
1. **贴边命中**（`hitShapeEdge`）：矩形/椭圆只认描边附近，内部不算。
   否则画面上有个大框，框里任何地方滚轮都去改框，想放大那块内容就放大不了。
2. **撤销分组**：`adjustSession` 记住当前调的是哪个图形，连续滚只 push 一次快照，
   900ms 不动或换图形才开新会话。否则滚十下要按十次撤销。
3. **闭包拿不到最新 state**：wheel 用原生监听（必须非 passive），所以把 shapes/scale
   同步到 `shapesRef`/`scaleRef`，并且 setShapes 时**手动更新 ref**，
   不然连续快速滚动会基于旧数组计算，增量丢失。

视觉反馈：悬停图形画紫虚线外框（线宽 1.6/scale，缩放后仍是 1.6 屏幕像素）+
底部胶囊提示"滚轮调整 · 粗细 8"，画布光标变 ns-resize。

### 锥尾箭头
`ArrowStyle = 'solid' | 'tapered'`，`drawArrow` 分两路。
锥尾的要点：尾宽 = max(5, strokeWidth*2.1)，两侧用二次贝塞尔，
控制点取轴向 62% 处再往轴心收 32% → **内凹**。直线连过去是个等腰三角形，很硬；
内凹才有笔刷拖过去的感觉。尾部再补一条 stroke 让平口变圆。

### 踩的小坑
- `shapesRef.current = shapes` 写在 ref 声明处会 TDZ 崩（layout 还没定义），
  必须放在 layout useMemo 之后。
- 开始画新图形时要 `syncHover(null)`，否则旧图形的高亮会一直挂着。

### 验证
`.tools/hover_test.py`（自己找紫色块定位"锥尾"按钮，避开顶栏的紫色"复制"）：
悬停 → 虚线框 + 提示"粗细 3" → 滚 5 格变 8（实拍确认线变粗）→
画实心箭头 → 切锥尾 → 画锥尾（尾宽头尖，实拍确认）。

## 第七轮补：锥尾箭头按老板定义重做

老板原话："锥尾箭头指的是箭头头部宽大，箭身（尾部）向反方向逐渐收窄，末端收成锐角尖角。"

第一版做反了——我做成了"尾宽头尖"的拖尾。重写成**飞镖形**：
尾尖(宽0) → 身逐渐张开 → 颈(0.62×头宽) → 头基(1.0×头宽，最宽) → 箭尖。

两个比例决定观感（别再动）：
- 头宽 = 粗细 × 5，下限 16。第一版是 ×3.2 下限 9，结果整条像一根线，看不出箭头。
- 颈宽 = 0.62 × 头宽。第一版 0.34，变成"火柴棍+三角头"；0.62 才有"张开"的箭头感
  同时身还是连着的。
- 头长 = min(整长×0.5, 头宽×1.15)，短箭头不会变成一坨。

身用二次贝塞尔，控制点外凸 0.06×颈宽 → 像磨过的刀身，不是硬直线。
画完再 stroke 一圈同色（lineWidth = 粗 × 0.3），消小尺寸锯齿。

验证：`.tools/arrow_shape.py` 一次画四条（长横/短横/斜/陡斜）实拍对比，
放大截图确认"宽头→针尖尾"的形状成立。

## 第七轮补 2：锥尾箭头加燕尾

老板："箭头需要燕尾"。

尾部从"一个锐角尖"改成"两个尾角 + 中间往头方向凹进去的 V 形缺口"。
路径：r1 →(贝塞尔)→ 颈 → 头基 → 箭尖 → 头基 → 颈 →(贝塞尔)→ r2 → 缺口顶点 → closePath 回 r1。

新增两个比例：
- 尾宽 backW = max(6, 头宽 × 0.34)：两个尾角之间的距离，太窄看不出分叉
- 缺口深 notch = min(backW × 1.35, 整长 × 0.18)：浅了像毛边，深了会吃掉身子

验证：`.tools/arrow_tail.py` —— 画一条 → 悬停滚到粗细 9 → 裁尾部特写，
实拍能看到清晰的双叉 + V 缺口。

## 第七轮补 3：燕尾在头部，不在尾部

老板更正："燕尾不是末端燕尾，是箭头头部"。

所以最终形态是：
**尾尖(锐角) → 身逐渐张开 → 颈(0.62×头宽) → 头基(1.0×头宽，最宽) → 两个前伸的叉 ┐**
**                                                        └── V 缺口 ──┘**

- 叉间距 = 头宽 × 0.92（prongHalf = 头宽 × 0.46）
- 缺口深 = min(头宽 × 0.55, 整长 × 0.22)，从**前端**往尾方向切进去
- 尾端回到单一锐角（上一版加在尾巴上的燕尾已撤掉）

路径顺序：尾尖 →(贝塞尔)→ 颈 → 头基 → 上前叉 → 缺口底 → 下前叉 → 头基 → 颈 →(贝塞尔)→ 尾尖。
上下对称靠 px/py 法线向量直接取正负，不用镜像矩阵。

验证：`.tools/arrow_head.py` 画一条 → 悬停滚到粗细 9 → 裁头部特写，
实拍能看到清晰的两个前伸叉 + V 形缺口。

## 第七轮补 4：锥尾箭头照老板给的 SVG 复刻

老板丢了个 `箭头.svg`（iconfont 那种 1024 画布的图标）。解路径拿到精确比例：

```
(332,706) 左肩外  (511,956) 箭尖  (690,706) 右肩外
(686,700)→(582,700) 右肩平线 → 身右边缘 → (515,68) 尾端
```

换算成以头宽 W 为基准：
- 头长 = 0.72W
- 身宽（头基处）= 0.38W
- 头宽 = 全宽 W，肩部从身宽**横出**到 W —— 这个横出的平台就是"燕尾"
- 尾端收成一个点（原图是 8.7px，可忽略）
- 全长 ≈ 2.5W

所以最终形状 = **细长锥身 + 平肩 + 大三角头**，全部直线，不用贝塞尔。
之前几版我一直在"V 形缺口"上打转，其实老板说的燕尾是**肩部横出那个造型**。

代码：`drawTaperedArrow` 六段直线 path，headLen = min(len*0.6, headW*0.72)，
shaftHalf = headW*0.19。头宽仍由粗细驱动（width*5，下限 16），
所以想要参考图那种夸张大头，把粗细滚到 15+ 即可。

验证：`.tools/arrow_head.py` 实拍，头是标准「细身 + 平肩 + 大三角」。
